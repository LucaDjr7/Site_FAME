### Verdict de mise en production : 🔴 **NO-GO en l'état**

Le code compile, passe le lint, et l'architecture de fond est saine (séparation service-role correcte, RLS activée, aucun secret en clair ni dans le bundle client ni dans l'historique git). **Mais** trois bugs de correction 🔴 et un petit noyau de failles 🟠 doivent être corrigés avant toute ouverture publique. Aucun n'est structurel — ce sont des correctifs ciblés, réalisables rapidement.

### Bloquants de déploiement (à corriger avant la mise en ligne)

| # | Sévérité | Constat | Domaine(s) | Emplacement |
|---|---|---|---|---|
| B1 | 🔴 | **Conversion de proposition → sujet orphelin** : en cas d'échec partiel, un sujet est créé sans lien proposition (état incohérent, pas de rollback) | D2 (F1) | `api/proposals/[id]/convert/route.ts:50-56` |
| B2 | 🔴 | **Réordonnancement silencieux** : les erreurs Supabase de `order` sont avalées, l'UI croit avoir réussi | D2 (F2) | `api/subjects/[id]/order/route.ts:10-14` |
| B3 | 🔴 | **Race condition sur `claim`** : deux membres peuvent réclamer la même tâche (lecture-puis-écriture non atomique) | D2 (F3) | `api/tasks/[id]/claim/route.ts:14-23` |
| B4 | 🟠 | **`GET /api/members` public** : expose la liste des membres et leurs emails sans authentification | D1 (#1), D2 (F9), D4 (CONV-03) | `api/members/route.ts:7` |
| B5 | 🟠 | **Écritures cross-lab non vérifiées** : les routes `[id]` ne valident pas l'appartenance au labo → un membre d'un labo peut muter les données de l'autre | D1 | routes `api/*/[id]` |
| B6 | 🟠 | **Injection HTML dans les emails Resend** : nom/contenu interpolés sans échappement dans le template HTML | D1 | `resend/send-proposal-result.ts:27`, `send-invitation.ts:25` |

> B4 à B7 sont des 🟠 promus au rang de bloquants : ils touchent la confidentialité des données (emails), l'intégrité cross-labo, ou cassent un parcours critique (activation de compte). Les autres 🟠 sont importants mais non bloquants pour un lancement contrôlé.

### Ce qui est sain (à conserver)

- `createServiceClient()` **ne porte pas** les cookies de requête → pas de bascule accidentelle sous RLS (piège classique évité, confirmé par D1).
- Aucun secret server-only (`SUPABASE_SERVICE_ROLE_KEY`, `DROPBOX_ACCESS_TOKEN`, `RESEND_API_KEY`) dans le bundle client ni dans l'historique git ; `.env.local` correctement gitignoré.
- `tsconfig` en `strict: true`, build sans `ignoreBuildErrors`/`ignoreDuringBuilds`.
- Parité i18n EN/FR parfaite : 357 clés de chaque côté, **0 clé désynchronisée**.
- Migrations Supabase ordonnées, idempotentes (`IF NOT EXISTS`), non destructrices.

## 2. Constats par domaine (après dédoublonnage)

### D1 — Sécurité & auth (🟠6 🟡9 ⚪7)

Constats 🟠 :
- **Sec-1 — `GET /api/members` public** → voir bloquant **B4** (dédoublonné avec D2/D4).
- **Sec-2 — écritures cross-lab** sur les routes `[id]` (subjects, tasks, publications, prompts) : pas de vérification que la ressource appartient au labo du caller → voir bloquant **B5**.
- **Sec-3 — `subjects/[id]/order`** : cross-lab + entrée non validée (tableau d'IDs accepté tel quel).
- **Sec-4 — `POST /api/comments`** : pas de rate-limit ni de bornes de taille (spam / payload volumineux possible).
- **Sec-5 — injection HTML dans les templates Resend** → voir bloquant **B6**.
- **Sec-6 — pas de rate-limiting sur `/api/auth/sign-in`** (brute-force ; mitigé partiellement par Supabase Auth selon config projet).

🟡 / ⚪ : durcissements divers (en-têtes de sécurité — voir D7, validation d'entrée plus stricte, journalisation). Voir `docs/audit-raw/D1-securite.md` pour le tableau route × méthode × rôle complet.

### D2 — API & correction (🔴3 🟠6 🟡6 ⚪3)

🔴 (tous bloquants — B1/B2/B3 ci-dessus). Autres constats notables :
- **F6/F7 — `PGRST116` mappé en 500 au lieu de 404** sur `PATCH subjects/[id]` et `tasks/[id]` (ligne introuvable traitée comme erreur serveur).
- **F8 — `DELETE /api/dropbox/links`** renvoie 200 même si aucune ligne supprimée (faux succès).
- **F5 — activate** : `update`/`delete` non vérifiés (résultat ignoré).
- **F9 — `GET /api/members` public** (= B4).

### D3 — Frontend & React (🟠9 🟡10 ⚪7)

🟠 notables :
- **F10 — keyframes `fameSpin` / `fameSpinRev` utilisées mais non définies** dans `globals.css` (`Globe.tsx:304`) → animation cassée.
- **F21 — `PromptCard.handleDelete` appelle `onDeleted` même en cas d'échec** (suppression optimiste fausse).
- **F06 — `PublicationList`** fetch sans vérifier `res.ok`.
- **F01 — `Globe`** lit `window` au render initial (risque d'hydratation).
- **F02 — closure périmée** dans le `useEffect` de drag.
- **F04 — `FilterSidebar`** utilise un hook sans `'use client'`.
- **F05 / F07 — `CommentsPanel` / `AdminProposalsClient`** : pas de feedback d'erreur / pas de `catch`.
- **F22 — `loadAtlas`** : `draw()` appelé après démontage.

### D4 — Qualité & dette (🟠6 🟡15 ⚪10)

🟠 notables :
- **CONV-01 — ~355 couleurs hex inline** au lieu des tokens `fame-*`.
- **CONV-02 — ~246 `fontFamily` inline** au lieu de `font-serif` / `font-mono`.
- **CONV-03 — `GET /api/members` sans auth** (= B4).
- **DUP-01 — `DiffDots` défini 3× avec des signatures différentes.**
- **DUP-02 — gradient `PAGE_BG` dupliqué ~8×** ; **DUP-04 — tableau `LABS` dupliqué 17×.**
- **TS-01 — `any` + aplatissement dupliqué** sur les jointures Supabase.

🟡 : **CFG-02 — `noUncheckedIndexedAccess` absent** du tsconfig (recommandé, voir annexe outillage).

### D5 — i18n (🟠6 🟡4 ⚪5)

- **F-HC-01 — kicker `FAME / {labLabel}` hardcodé** dans 4 composants (`PublicationList`, `DataExplorer`, `PromptLibrary`, `MemberGrid`).
- **F-HC-02 — `FAME / Admin` hardcodé** (`AdminProposalsClient.tsx:129`).
- **F-HC-03/04/05 — `aria-label`/`title` non traduits** (`Globe.tsx:336`, `SubjectCard.tsx:69`, `DataExplorer.tsx:568,830`).
- **F-HC-06 — placeholders d'exemple hardcodés** (`InviteModal`).
- **19 clés mortes** (namespace `common.*` à 12/14 inutilisé, `tasks.history`, `paper.saved`, etc.) — dette d'entretien, non bloquant.
- **F-FR-01/02 — `Preprint` / `Working paper`** non traduits en FR (acceptable en contexte académique).
- ✅ **0 clé manquante**, **0 désynchronisation** EN/FR.

### D6 — Perf / a11y / UX / SEO (🟠7 🟡19 ⚪5)

🟠 notables :
- **A1 — `Modal` sans `role="dialog"` / `aria-modal` / focus-trap** (`Modal.tsx:16`).
- **A2 — labels de formulaire sans `htmlFor`** dans tous les modaux.
- **A3 — `TaskCard`** : `div onClick` non focusable au clavier (`TaskCard.tsx:23`).
- **A4 — arborescence Dropbox** : `div` cliquables non focusables (`DataExplorer.tsx:428`).
- **A5 — canvas du globe sans `aria-label`.**
- **S1 — zéro `metadata` par page** (title/description génériques partout, SEO nul) ; **S2 — pas de `sitemap.xml`/`robots.txt`.**
- **U1 — double-soumission possible** (`CommentsPanel`).

🟡 : perf (Globe rAF sans pause onglet caché, Google Fonts sans `preconnect`, `Avatar` `unoptimized`, absence de `prefers-reduced-motion`, comptages sans `useMemo`), UX (pas de `loading.tsx` RSC, focus non restauré après fermeture de modale).

### D7 — Config & déploiement (🟠1 🟡5 ⚪6)

- **🟠 `NEXT_PUBLIC_APP_URL` non gardé** → voir bloquant **B7**.
- **🟡 aucun en-tête de sécurité HTTP** (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, CSP) — `next.config.ts` vide.
- **🟡 protection admin au niveau page, pas layout** : `admin/layout.tsx` n'appelle pas `requireAdmin()` ; une future page `/admin/xxx` sans garde serait exposée.
- **🟡 pas de `.env.example`**, **email admin hardcodé** dans `seed-admin.ts`, **pas de CLI Supabase** (`config.toml`).

## 3. Plan de remédiation suggéré

> Ordre de priorité. L'audit étant lecture seule, ces correctifs sont à exécuter dans une session/branche d'implémentation dédiée (pas ici).

**Vague 0 — bloquants avant mise en ligne (B1–B7)**
1. B1 : envelopper la conversion proposition→sujet dans une transaction (ou compenser/rollback en cas d'échec) — `convert/route.ts`.
2. B2 : vérifier `error` de Supabase dans `order`, renvoyer 500 explicite sur échec — `order/route.ts`.
3. B3 : rendre `claim` atomique (update conditionnel `WHERE assignee IS NULL` + vérifier la ligne affectée) — `claim/route.ts`.
4. B4 : exiger `requireMember()` (ou `requireAdmin()`) sur `GET /api/members`, et restreindre les champs exposés — `members/route.ts`.
5. B5 : ajouter une vérification d'appartenance au labo sur chaque route `[id]` mutative.
6. B6 : échapper le HTML interpolé dans les templates Resend (helper d'échappement).
7. B7 : guard explicite sur `NEXT_PUBLIC_APP_URL` (erreur claire si absent au lieu de fallback `''`).

**Vague 1 — correction & robustesse (🟠 restants D2/D3)**
- F6/F7 (PGRST116→404), F8 (DELETE faux 200), F5 (activate non vérifié).
- F10 (keyframes `fameSpin` manquantes), F21 (`onDeleted` sur échec), F06/F05/F07 (`res.ok`, gestion d'erreur), F01/F02/F22 (hydratation, closures, post-démontage).

**Vague 2 — a11y & SEO publics (D6)**
- A1/A2/A3/A4/A5 (ARIA modaux, labels, focus clavier), S1/S2 (metadata par page, sitemap/robots), `prefers-reduced-motion`.

**Vague 3 — durcissement & config (D1/D7)**
- En-têtes de sécurité HTTP, `requireAdmin()` dans `admin/layout.tsx`, rate-limit `comments` et `sign-in`, `.env.example`.

**Vague 4 — dette & i18n (D4/D5)**
- Extraire tokens couleur/police inline, dédupliquer `DiffDots`/`LABS`/`PAGE_BG`, kickers i18n, purge des 19 clés mortes.
