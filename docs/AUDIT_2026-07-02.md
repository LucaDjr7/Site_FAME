## 2. Findings par domaine

Chaque finding 🔴/🟠 est marqué « contre-lu ✓ ». Détail complet dans les rapports bruts `docs/audit-raw/2026-07-02/D*.md`.

### D1 — Sécurité & Auth

**Chaîne `confidentiel` : conforme et vérifiée** — grille Lab, page Paper (sujet/tâches/commentaires/fichiers/`generateMetadata`), `GET /api/subjects[/…]`, `/api/tasks[/…]`, download `files/[fileId]` (gate `subject.confidentiel OU file.confidentiel` → 404), `match_rag_chunks` (tier opposable côté SQL), tous les outils de l'assistant, et l'héritage mère→fille (fail-safe : mère absente → aucune résolution, le CRITICAL de PR #48 reste fermé). 37 routes : toutes les méthodes mutantes exigent ≥ `requireMember`.

- **🟡 R1 — Relations vers sujets confidentiels dans le payload RSC (graphe + Paper)** — contre-lu ✓. `graph/page.tsx:29` charge `subject_relations.select('*')` sans filtre et le passe au client ; `paper/[id]/page.tsx:62` idem. Le rendu masque, mais UUID + topologie + libellés `label`/`label_i18n` de sujets confidentiels restent dans le HTML/flight envoyé à l'anonyme. Fix : filtrer côté serveur aux relations dont les deux extrémités sont visibles.
- **⚪ R2** — `DELETE /api/admin/logs/[id]` : `type in DELETABLE` traverse le prototype (admin-only, non exploitable, produit un 500). Fix : `hasOwnProperty.call`.
- **⚪ R3** — `POST /api/comments` : pas de gate `confidentiel`/existence sur `sujet_id` (écriture possible sur un sujet confidentiel dont on connaît l'UUID ; lecture reste gatée).

### D2 — API & Données

Corrections de l'audit 06-28 (B1, B2-tâches, I2, I3/I4, I5, M5, M13, path-traversal `..`) **toutes vérifiées toujours actives**.

- **🟠 Suppression d'un sujet : fichiers Storage jamais purgés** — contre-lu ✓ (lecture directe de `subjects/[id]/route.ts:88-92` + `schedule.ts`). Le FK `on delete cascade` supprime les lignes `subject_files` avant le `after()`, qui ne purge que les chunks RAG ; aucun `storage.remove`, `storage_path` déjà perdu. Orphelins permanents. Fix : lire les chemins avant le delete, planifier `storage.remove`.
- **🟠 `reindexAll` n'indexe jamais `subject_files`** — contre-lu ✓ (`index-source.ts:198`, boucle sur `subjects/publications/prompts/members/tasks` + KB). « Réindexer tout » laisse les 131 chunks de documents intacts. Fix : ajouter la boucle `subject_files`.
- **🟡** Anti-cycle relations : TOCTOU sous concurrence (pas de verrou) → cycle possible, casse l'hypothèse DAG de `resolveInheritance`.
- **🟡** Toggle `confidentiel` pendant l'indexation initiale : fenêtre où un chunk peut rester en tier périmé jusqu'au prochain retier.
- **🟡** Register : `mime_type`/`size_bytes` déclarés non vérifiés contre l'objet réel.
- **⚪** `subtasks` → 500 au lieu de 404 sur id invalide ; `DELETE …/relations/[relId]` ignore le paramètre `id`.

### D3 — Frontend / React

Aucune fuite confidentielle côté client, aucune mutation Supabase directe.

- **⚪** Props mortes `logsHref`/`backHref` ; ref callback recréé ; heuristique `router.back()` (limite connue) ; `AuthButton.signOut` sans try/catch.

`tsc`/`lint` exit 0 · **432/432 tests** · `npm run build` exit 0 · `npm audit` = 3 moderate, 0 high/critical. Conforme à la baseline STATUS.md.

### État réel de la BDD Supabase de dev (`etat-bdd.md`)
- **Migrations `001`–`014` toutes matérialisées** (tables/colonnes/RPC vérifiées une à une). `match_subject_files` (011) et `tasks.i18n` (012) **présents** → l'ambiguïté documentaire de D7 est empiriquement levée.
- Bucket `subject-files` = **privé**. RPC `match_rag_chunks`/`match_subject_files` = OK.
- **Sonde RLS anonyme** : toutes les tables sensibles (`subjects`, `members`, `subject_files`, `subject_relations`, `rag_chunks`, `proposals`, `prompts`, `dropbox_links`) → **0 ligne lisible en anonyme** (default-deny effectif ; l'accès public passe par les RSC/API service-role).
- Index RAG : 349 chunks (kb=136, subject_file=131, subject=78, task=3, member=1) ; visibility public=339 / member=10.

### Sonde HTTP — GET anonymes sur build de prod local (`sonde-http.md`)
- Pages publiques : toutes 200 (lab invalide → 404). Headers de sécurité (HSTS inclus) tous présents ; CSP absente (différée).
- **Gates confidentiel vérifiés en réel** : `GET /api/subjects/<confi>` → 404 ; download doc confidentiel → 404 ; `/api/subjects?lab=paris` anonyme → 11 sujets, **aucun confidentiel** ; sujet public → 200 (contrôle). **Le titre du sujet confidentiel n'apparaît sur aucune page.**
- **Nouveau finding dynamique (🟡)** — **le gate membre du middleware est mort pour `/data` et `/prompts`.** `MEMBER_ONLY_PATHS = ['/data','/prompts']` est comparé à `pathWithoutLocale` qui **conserve le segment lab** (`/paris/data`), donc la condition ne matche jamais les vraies routes lab-préfixées. Aujourd'hui **sans conséquence** : le RSC `redirect()` de chaque page backstoppe (vérifié : `/en/paris/data` anonyme renvoie le flight `NEXT_REDIRECT;replace;/en/auth/login`, aucun contenu `DataExplorer` — les chaînes « Dropbox » viennent du dictionnaire i18n, pas du composant). Mais la défense-en-profondeur au edge est absente : une future page membre qui s'appuierait sur le middleware fuiterait. `/admin/*` n'est pas affecté (non lab-préfixé → gate OK, 307 vérifié). Fix : comparer sur le path sans le segment lab, ou déplacer la garde.
- **Soft-status (⚪)** — `notFound()`/`redirect()` renvoient **HTTP 200** (Next streaming : la redirection/404 est encodée dans le flight, exécutée côté client). Aucune fuite de contenu (vérifié). Impact SEO/correction uniquement (un crawler non-JS voit 200 + coquille). Envisager un `not-found.tsx` de segment.
